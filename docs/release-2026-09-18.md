## Verification

- Full production backup restored into an isolated local PostgreSQL 17 instance. The complete migration applied successfully; authenticated feed/rankings and service-only quota/recap/media/deletion SQL smoke checks passed. Test changes rolled back and the local container had no network access.
- 44 regression tests and TypeScript passed after the migration compatibility fix and venue-policy regression test. ESLint passed with 0 errors and 104 warnings. The lockfile was repaired and verified with Linux Node 22 `npm ci --dry-run` after CI found two missing optional peer dependencies.
- Live migration history and function grants verified. Anonymous identity lookup, karaoke advancement and service quotas are denied; both private media buckets remain private.
- Live password-login CORS preflight returned 204; invalid credentials returned 401. Image moderation, deletion, registration and AI endpoints rejected unauthenticated calls with 401.
- Production desktop login rendered without browser runtime errors.
- No historical registrations, payment events or push tokens required data reconciliation.
- The authenticated GitHub keep-alive workflow was configured and passed after restoring Supabase. Vercel reported no runtime errors in the post-promotion verification window.

Supabase's remaining advisories include the intentionally public profile/standings views, callable SECURITY DEFINER functions, legacy tables with no policies, the pg_net extension location, and disabled leaked-password protection. These need separate policy-by-policy review; the release is not a claim that every advisory has been eliminated. See [Supabase database linter guidance](https://supabase.com/docs/guides/database/database-linter).

Real provider payment completion, image moderation and notifications still require authorized staging accounts/device testing. No real payment, push send or account deletion was performed.

## Native release

Production EAS client environment variables and the existing Sentry upload secret are configured. Android build `f1de6f7f-9727-440e-b8b9-be5b9801eaeb` (version code 6) is queued; Expo reports elevated Android build/submission queue times. EAS has an Android keystore, but no Google Play submission service account or FCM v1 credentials. iOS build setup is blocked because signing credentials are missing from EAS. Store publication requires those credentials to be configured.

The native runtime now uses a fingerprint policy and updated native dependencies. Older installed binaries need a new store build; publishing an OTA update alone cannot update them.

EAS updates were published to the `production` branch: Android group `296a71b7-9da7-4b51-a47a-7466de935969`, iOS group `ca98efed-9bb1-42dd-9e46-66f17c7fea9a`. They only apply to compatible fingerprint runtimes.
